# Clarify a design with durable notes

Read the sibling `grilling` and `domain-modeling` skills when they apply. Inspect the relevant code and existing documentation first.

Resolve only uncertainties that affect behavior, compatibility, data, scope, or meaningful design alternatives. Keep verified facts, open questions, and recommendations separate. Record accepted terminology and durable architecture choices in the existing project locations.

When the request is sufficiently defined, move into the authorized implementation or return the requested design. A glossary update or ADR does not require a separate confirmation when it records an accepted decision. Do not turn a routine fix into an interview or require confirmation of every technical choice.

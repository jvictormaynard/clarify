# Improve the Clarify workflow from evidence

Read the relevant task artifacts, current checks, and instructions. Keep the review inside this repository; do not inspect or edit global instructions as part of a project retrospective.

Identify repeated friction or a demonstrated failure in navigation, feedback, tests, review, environment access, or instruction load. Separate an observed cause from a speculative improvement. A check that exists but was skipped needs repair or routing, not a replacement framework.

For each useful improvement, give evidence, the smallest correction, expected effect, maintenance cost, and how to verify it. Prefer deterministic checks for mechanical invariants and concise decision rules for design judgment.

Implement local process fixes when the user authorized them; otherwise present the candidates. Do not add a universal rule for every one-off event. Preserve the release gates and measure actual workflow results before claiming a speed or quality gain.
